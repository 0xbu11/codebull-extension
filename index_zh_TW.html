我讓八個 goroutine 同時寫進 leveldb，它每一波都只寫兩次 WAL

同樣每秒 24 筆，一個寫入者換成八個。5,760 次 Put 換來 1,440 次 WAL 寫入：720 波，每一波都是第一個人自己寫、第二個人帶走另外六個。leveldb 裡一個點都不掛，形狀還在；毫秒數就不在了。

我盯著一個 singleflight 看了十分鐘，然後看到同一個逾時被一次發給了七個人

我拆掉自己的觀測點，那條 55 毫秒的尾巴就消失了

即將推出

搶先預覽即將登場的 CodeBull Agent

從模糊症狀更快走到正確的觀察路徑。這段產品預告說明了未來推出的 CodeBull Agent 將如何協助你規劃可觀測性流程中的下一步。

從自然語言開始

規劃中的體驗會讓你直接用日常語言描述延遲飆高、行為不穩定或錯誤訊息過雜等問題，而不是先被工具選單綁住。

更快找到下一步

未來推出的 Agent 預計會協助你判斷接下來應該先看日誌、指標、儀表板，還是火焰圖，減少在不同面板之間盲目切換。

讓調查不中斷

正式提供後，Agent 預期會成為調查流程中的即時助手，幫助你快速縮小範圍、對照不同訊號，並決定先驗證哪個方向。

為什麼選擇 CodeBull？

動態日誌 (Dynamic Logging)

立即注入日誌語句以擷取變數值。獲取您需要的資料，而不會污染您的原始碼或弄亂 git 歷史紀錄。

即時指標 (Instant Metric)

立即將計數器和儀表附加到任何程式碼行。追蹤命中率和變數趨勢，無需定義全域變數或手動註冊指標。

歷史儀表板 (History Dashboard)

從本地插樁歷史資料一鍵產生監控儀表板並開啟可分享的報表頁面。可檢視跨點位趨勢，涵蓋最多 30 天快取資料。

火焰圖分析 (Flamegraph)

我們現在支援火焰圖分析。可直接從 VS Code 檢視堆疊樣本與熱點分布，更快找出執行路徑中的瓶頸。

Runtime 儀表板 (Runtime Dashboard)

在 VS Code 中即時監控 goroutine 數量、Heap 記憶體配置、GC 次數與處理器狀態。無需加入 pprof 端點，無需修改程式碼——連線即可觀測。
