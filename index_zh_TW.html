實測筆記

CodeBull 在真實服務上跑出來的東西

對執行中的 Go 服務實際掛觀測點的紀錄。文中每一條 SQL、每一個數字都出自實測數據，並附上遠端面板可線上對帳。

GORM · 實測筆記

我盯著一個跑著的 GORM 看了八分鐘，然後看到它把主鍵弄丟了

不改一行 code，在 GORM 內部掛兩個觀測點：soft delete 把 DELETE 改寫成 UPDATE、一個 Preload 變成兩條 SELECT，還有一條 UPDATE 退化成全表形狀——全部當場看到。

閱讀文章 → Redis · 實測筆記

我盯著 Redis client 送上線的每一個 token，然後發現我存了一串不該存的東西

一行 HSet 在線上是六個有序 token；而一個直接用 SET 存進去的 time.Time，把 Go 的 monotonic clock 讀數一起寫進了 Redis。

閱讀文章 → Gin + GORM + MySQL · 實測筆記

我在 MySQL driver 的門口站了八分鐘，然後看到一次「改個數量」寫了三張表

驅動門口兩個點、應用層三個計數：一次列表查詢是 3 條 SQL 而不是 N+1，一次 PUT 在底下展開成六條，而一個沒人操作的分頁每秒要走 8 條查詢。

閱讀文章 → GORM · Metric + Log + Latency

一個收斂點，三種真相：多常、什麼、多久

Metric、Log、Latency 掛在 GORM 同一個函式上：947 次入口命中、8 種逐字 SQL 形狀，以及 p95 是中位數十倍的尾巴——全部出自同一個五分鐘窗口。

為什麼選擇 CodeBull？

動態日誌 (Dynamic Logging)

立即注入日誌語句以擷取變數值。獲取您需要的資料，而不會污染您的原始碼或弄亂 git 歷史紀錄。

即時指標 (Instant Metric)

立即將計數器和儀表附加到任何程式碼行。追蹤命中率和變數趨勢，無需定義全域變數或手動註冊指標。

歷史儀表板 (History Dashboard)

從本地插樁歷史資料一鍵產生監控儀表板並開啟可分享的報表頁面。可檢視跨點位趨勢，涵蓋最多 30 天快取資料。

火焰圖分析 (Flamegraph)

我們現在支援火焰圖分析。可直接從 VS Code 檢視堆疊樣本與熱點分布，更快找出執行路徑中的瓶頸。

Runtime 儀表板 (Runtime Dashboard)

在 VS Code 中即時監控 goroutine 數量、Heap 記憶體配置、GC 次數與處理器狀態。無需加入 pprof 端點，無需修改程式碼——連線即可觀測。
