Five lines of Go in a loop, 3,638 tokens on the wire

2026-08-307m20s window / 1,070 commands / 4 probesgo-redis v9 + Redis 7

📊 The numbers here come from this run’s remote dashboard: redis-observing-runtime-20260830

Probes from the command entry all the way down to the line that writes a token, on a running go-redis — no code change, seven minutes twenty.

Why these four places

The loop runs five lines of Go every two seconds: INCR, SET, HSET, SADD, ZADD. The command count is arithmetic — but the strings that actually leave the process are not: four layers sit between the argument and the wire.

So four probes follow one path down: baseClient.process, withConn, writeCmd, and proto.Writer.WriteArg. The unit changes at every step: request → connection → command → token. Seeing where the unit changes is the whole point of the path.

What each signal says here

metric (how often) — the three upstream nodes are all 1,070, ×1 the whole way: every command borrows its own connection and encodes its own RESP, nothing shared and nothing leaked. Only at the last layer does it become 3,638.

latency (how long) — on the process interval: p50 4.294ms, p95 12.639ms. That is a full round trip, network included.

log (what) — the token probe captures v and ranks the deduplicated strings by count. CodeBull appears 657 times against 219 for every other token — three times over: HSET, SADD and ZADD each write it once per round. From the caller this is invisible, because the caller sees three different commands.

flamegraph (from where) — on the dashboard’s Call stack tab the token node has five frame chains, one per command: HSet 1,314, SAdd 657, ZAdd 657, Set 657, Incr 438 (those five come from the dashboard’s full window and add up to 3,723; the graph at the top of this piece uses a slightly narrower window, 3,638). One line of code reached by five different paths, and the spread between them *is* the argument count of each command. The ZAdd chain even carries an extra ZAddArgs frame — it takes one more hop than the others.

What came out

3,638 ÷ 1,070 = ×3.4. That number appears in no line of code, because it is the average argument count — a property of the data, not of the program. Change the keys, add one field to the HSET, and it moves.

The edge from Borrow a connection to Encode the command is labelled 3 unobserved and lists _process.func1, pool.(*Conn).WithWriter, _process.func1.1 — the acquire-and-release path. Nobody probed it, so the graph draws a dashed edge with names on it rather than pretending to see.
