Ristretto · Field Notes

It said yes 736,182 times and kept a thousand

The caller's 736,182 Set calls all returned true, while the cache's own counters say it rejected 684,408 and evicted 49,834 more. On the graph, Admit or reject is a root of its own — that true never meant "kept", only "queued".

gin · Field Notes

I counted a running gin for eleven minutes and saw the eight shapes of a middleware chain

600 requests, 1,800 advances, ×3 on average — but the stacks hold eight distinct chains: the 401 phase loses the last one, and the 301 phase never reaches the chain at all. Measured along the way: the 54.6 ms p95 is 82 samples, all of them in the four phases that run the chain, against 0.166 ms in a control round with only the entry probe.

etcd · Field Notes

A read also knocks on the WAL

Six probes along the whole write path, traffic in five phases. The four request-side probes all read 9,472, while wal.Save was entered 22,555 times, ran to the end 17,404 times, and etcd counted only 9,421 fsyncs. In the last phase, which sent reads only, Save gained 5,151 more — exactly the number of reads the client sent.

One Preload, one extra statement on the read path

GORM bracketed from both ends: 286 calls to First, 429 runs at the convergence point, and the extra 143 are what Preload expands into at run time. Of the 1,144 executions, 143 more have no upstream at all — that is Delete, the one call this round with no probe on it.

Redis · Field Notes

I almost published a very tidy wrong conclusion

Five probes over seven minutes, and every token accounted for: 648 + 13 × 216 = 3,456, plus one last_run value per round, making exactly 3,672. Then, to find how much of the latency was the observation itself, I ran a control — +28.1% the first time, −1.2% the second, in opposite directions.
