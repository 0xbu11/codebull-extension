One Preload, one extra statement on the read path

2026-08-286m40s window / 137 rounds of CRUD / 7 probesGORM + PostgreSQL 16

Probes on a running GORM, from four API callers down to the line that emits the statement — no code change, six minutes forty.

×1.5: called twice, executed three times

Over the window First() was called 274 times, while the ORM underneath executed 411. The extra 137 come from Preload("User") — one chained call that expands into a second query at run time. The ratio is written in no line of code; you only get it by counting.

The dashed edge names what it cannot see

That edge is labelled 0–4 unobserved, and it lists them: Find, preload, preloadEntryPoint, Preload. The extra query is emitted from inside those four frames. The graph does not pretend to see them, but it does tell you where they are.

A caller with no probe becomes its own island

137 of the 1,096 executions have no upstream on the graph. That is Delete(), the one call in this round with no probe on it. With the caller off the graph, its executions show up as a second starting point instead of being attached to somebody else.

The Emit the SQL node lists the 8 distinct statements that actually left the process this round, 133 each. Across the window p50 was 0.93ms and p95 57ms.
